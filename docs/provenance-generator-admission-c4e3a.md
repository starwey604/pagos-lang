# 封闭生成器准入 C4e3a

日期：2026-10-28。承接 [C4e2b](provenance-scalar-cli-c4e2b.md)，实现
[实施计划](cache-implementation-plan.md) 的 C4e3a。该轮交付生成器的版本化
描述和从 checked AST 得到的元素独立性依据。尚未记录真实数组计算、执行
选定元素或扩展 explain-replay；这些继续由 C4e3b/C4e3c 承担。

## 描述与语义边界

GeneratorReplayDescriptor v1 使用独立 CAS ObjectKind 16，内部保留生成器
语义版本和标量操作语义版本，QueryKey/预算协议仍分别核验。已有标量描述
v1 的布局、指纹域和能力索引保持兼容。

描述包括：

- 原始纯特化 QueryKey，包括全部参数的类型和 Comptime 值，连同未使用
  参数一起构成完整捕获快照；Runtime、数组、记录和指针捕获不准入。
- 当前模块依赖指纹、生成器位置和迭代变量位置，均绑定定义语义指纹。
- 显式迭代槽，固定为参数槽之后的下一个槽，类型固定为 u32。
- 开始、结束和元素三个独立标量配方，分别包含结果类型、结构位置和有序
  节点。节点只可引用前面的节点，全部节点必须贡献到配方结果。
- 函数声明的具体数组类型，元素为受支持的整数或 bool。

范围沿用 Stage 的 u32 半开区间 `[begin, end)`。边界配方只能读取捕获；
元素配方额外允许读取迭代槽。迭代变量与参数同名时，元素中的名字绑定到
迭代槽，边界中的名字仍绑定原参数。不根据名字相同把两者混为同一个输入。
不要求元素实际使用迭代槽，常量元素同样可以独立。

本轮不执行边界运算，不断言区间递增或长度匹配，也不证明计算一定成功。
例如纯除零、非法移位和空区间仍可以有独立的表达式描述，后续必须由真实
成功的 Stage 记录和有界执行验证运行合法性。没有预期数组值或结果指纹，
描述不能冒充已发生的计算。

## 源码准入与独立性

admit_generator_replay 只接收已成功检查的 AST、匹配的 TypeTable 和当前
特化键；重新构建当前源码 identity，核对目标、函数签名和完整参数快照。
只接受内部函数的唯一尾生成器，函数及生成器体均不得包含语句。

边界与元素共用已有的纯标量白名单：类型化整数/bool 常量、参数、明确的
一元运算和二元算术/位运算/比较。拒绝调用、全局读取、数组索引、指针、
转换、分支、短路、嵌套生成器，以及任何声明、赋值、循环或 return 语句。
即便一个纯辅助函数能够内联，也不在此轮偷偷扩大准入。

因此，元素可读取的全部状态恰好是不可变捕获与本次 u32 迭代值，没有
其他迭代的结果、可变累加器、外部效果或未验证词法捕获。这是 v1 元素
独立性的依据，不是从最终数组值反推的历史。

成功返回拥有独立数据的 GeneratorReplayAdmission；构造函数私有，只能从
源码准入取得，不可通过反序列化描述获得。它不保存 AST 指针，也不表示
已经执行或验证了数组。跨进程读取描述后必须再次对当前源码准入。

validate_generator_replay 完整重建并逐项比较描述，包括操作、每个操作的
源码位置、常量、槽号、三个配方及依赖。结构合法但换了运算符、捕获槽或
源码位置的描述也不能取得凭据。空白变化保留语义身份并使用当前源码重定位；
定义、依赖、参数、目标或编译器上下文变化拒绝。缺描述明确不可用。

## 有界编码与存储

编码为 PGC1/kind 16：描述版本、生成器语义、标量语义、长度前缀 QueryKey、
依赖摘要、两个长度前缀 Anchor、迭代槽、声明数组类型和三个配方。配方为
长度前缀结果 Anchor、类型、节点数和紧凑节点记录。整数沿用目标无关编码。
新指纹域为 `pagos.generator-replay-descriptor.v1`。

codec 只验证结构。源码对应性和独立性必须经过源码准入，真实运行结果必须
经过后续记录与执行核验。这三个层次不会通过一个可伪造的布尔标志合并。

整个对象受字节/字符串限制，三个配方共享节点总额度；解码在分配节点前
核对剩余额度和输入长度。源码扫描受 identity 的元素与深度限制，表达式
构建另受剩余节点数和深度限制。平坦节点引用检查及可达性检查使用迭代算法。
分配失败、未知版本、额外尾字节、截断和不规范类型均显式返回错误。

FileStore 可显式保存/读取 kind 16 对象。默认编译尚不发布该对象，也没有
新的生成器能力索引；原 C2 数组值和 ResourceRecipe 不会自动变成独立性证据。
本轮没有数据库、解释副作用或 Stage 预算变更。

## 验证与后续

新增 13 项 GeneratorReplay 单元测试，覆盖完整/未使用捕获、迭代变量遮蔽、
bool/有符号整数/usize 和 32/64 位目标、常量元素、状态/效果/嵌套/调用拒绝、
Runtime 与签名/目标不符、结构合法的源码伪造、源码/依赖变更、空白重定位、
逐字节截断、版本/长度/节点总额、缺失语义事实及显式 CAS 读取后再次准入。
纯除零、非法移位、空范围和计算得到的巨大范围可以被描述，但没有执行或
结果成功承诺。Stage 对照覆盖正常编译、Fuel 不足和数组构建预算不足，
11 项分析统计、诊断、HIR 与成功时的残留 MIR 均保持一致。

验证结果：

- Debug 全套 469/469，包含 lit。
- GCC 串行 468/468，排除 lit。
- ASan/UBSan 468/468，排除 lit。
- 新生成器与既有标量描述/记录/执行的聚焦测试 44/44。
- 文档检查 52 个文件、clang-format 和 git diff --check 通过。

GCC 沿用串行验收；[C4e2a](provenance-scalar-execution-c4e2a.md) 记录的旧
并行测试偶发问题未在此轮定位或修复，不据此声称并行稳定性已恢复。

C4e3b 将在实际成功的数组计算中记录已核验范围、完整结果与描述，隔离
能力索引，并在独立预算中重放选定元素、核验原数组对应值。C4e3c 接入
显式 CLI 与跨进程/effect harness。C3 图仍为 P0。
