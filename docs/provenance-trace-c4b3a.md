# RuntimeTrace 前缀共享与真实 Stage 测量 C4b3a

状态：2026-10-16 完成 C4b3 的第一小轮。消除普通 RuntimeTrace 传播中的
整条路径复制，新增真实源码的独立构建/原生查询测量。本轮结束时完整 C4b 尚未完成；
剩余工作见[实现计划](cache-implementation-plan.md)。

## 表示、语义与释放

旧 RuntimeTrace 为每个表达式持有 `vector<string>`。对链式绑定，前一个
路径不断复制到下一个表达式，保留所有前缀可能占用平方级路径存储。
这发生在 HIR 中；仅把 Provenance 节点封块写盘无法消除这部分内存。

[RuntimePath](../include/pagos/hir/runtime_path.h) 用共享尾句柄引用不可变的
前驱链；复制只复制句柄和长度，追加分配一个新 Step。不同绑定和调用
持有自己的尾句柄，追加不修改共享前缀。普通追加的存储随实际新步骤增长。
它仍是原有的首来源诊断路径，不能代替完整 Provenance 来源查询。

参数重绑定按原顺序连接调用方路径和符号路径，不省略重复步骤。诊断、
`explain-stage` 及残留模板编码才展开成有序字符串数组。模板 wire 格式和
校验规则不变，旧的来源/参数重绑定语义不变；读取模板先校验数组，再构造
共享路径。当前解码不跨表达式驻留路径，因此模板编码大小、展开时间和
热模板恢复的最坏开销仍可能是平方级，不属于本轮优化承诺。

[Step 析构](../lib/hir/runtime_path.cpp) 迭代拆除独占的前驱链，遇到共享
前缀停止，避免长链 shared_ptr 析构递归。内部没有对 Step 的 weak 引用，
独占祖先才可拆除。200,000 步独占后缀释放后，共享前缀仍有效。
移动后源路径重置为空，可继续使用；复制和追加保留各自路径的顺序。

`RuntimePath::Accounting` 是显式的存储 census，同一批仍存活的路径加入
同一个收集器，按 Step 地址去重。报告句柄数、展开后的逻辑步数、唯一
Step 数与 Step/堆字符串容量。它不参与默认编译，不计 shared_ptr 控制块、
分配器、句柄本身、origin_name 或统计索引；统计期间路径必须保持存活。
不能把这个计数当作进程总内存或全工作集上限。

历史 [provenance_bench](../tools/provenance_bench/main.cpp) 显式保留原有
vector 路径基线，避免旧图/路径实验的比较对象随本轮变更而悄悄改变。

## 测量协议

[专用工具](../tools/stage_spill_bench/main.cpp) 解析并类型检查真实 `.pgs`：
两个函数 `a`/`b` 各有 N 个命名算术绑定，各以 Runtime 实参调用一次。
语义缓存关闭；分别运行 memory 和显式 spill。配置为 32 KiB 封块阈值、
256 KiB owned 驻留额度、64 KiB 读取缓存和 256 MiB 磁盘额度，失败策略为
辅助不可用。每个样本使用新任务目录，不发布函数或模块快照。

[脚本](../scripts/benchmark_stage_spill.py) 运行三类独立子进程：

- `build`：仅运行 Stage，不进行来源查询、证据导出或兼容整图恢复。
- `query`：完成相同 Stage，再通过原生 EvidenceView 查询 `aa` 的全部来源。
  前端、Analyzer 和 HIR 保持存活，验证节点/站点/根/决策、Fuel、来源及状态数
  与改动前 memory/spill 一致。spill 必须保持 `materialized=0`。
- `census`：另起进程遍历当前模块 HIR 和绑定 trace，统计共享路径。
  其去重索引会额外分配内存，所以不混入前两类的时间/RSS 分布。
  不覆盖 Analyzer 私有表独占保留的表达式，不宣称峰值工作集已计量完整。

每档每模式预热 2 次、测量 7 次。Linux wait4 RSS 是整个子进程高水位，
包含启动、前端、Stage、枚举文件、退出清理及所选查询，不是隔离的查询
峰值。阶段时间在工具内分开记录；墙钟包含退出清理。样本共享 OS 页缓存，
不代表物理磁盘冷启动。无绑核、无固定频率，构建和回归结束后顺序测量。

保留改动前 Release 工具二进制，并在当时记录源码、二进制及 CMake 身份。
该基线来自已有未提交改动的工作区，不能只用 HEAD 重建。报告保留两套身份
和全部样本；默认脚本仅运行当前版本，传入配对的 `--baseline` 与
`--baseline-identity` 才运行旧版对照。历史 C4a3 导出进程数据不混入本轮。

CAS 计数是成功的逻辑 payload 读写，不是总系统 IO，未包含 FileStore 发布
校验读、失败尝试、目录/manifest 操作或物理设备成本。文件大小另含每块
49 字节封装。正常退出后任务目录必须为空；该检查不替代进程崩溃测试。

## 本机结果

[原始 JSON](../benchmarks/results/stage-spill-c4b3a.json) 保存 32 组各 7 个
正式样本、每组 2 次预热配置、8 个独立 census 样本、范围/IQR 和前后身份。
本机为 AMD Ryzen AI 9 HX 470、Linux 7.2.10、Clang/LLVM 23.1.1、
Python 3.14.8。以下均为中位数，RSS 单位 MiB。

仅构建，不查询、不导出：

| N/函数 | 旧 memory RSS | 新 memory RSS | 旧 spill RSS | 新 spill RSS |
| --- | --- | --- | --- | --- |
| 128 | 28.61 | 27.12 | 29.50 | 27.80 |
| 512 | 51.66 | 29.02 | 48.58 | 29.66 |
| 1024 | 114.95 | 31.57 | 115.91 | 32.23 |
| 2048 | 376.57 | 36.74 | 377.16 | 37.01 |

最大档仅构建的 RSS 范围为旧 memory **376.06–376.81 MiB**、
新 memory **36.53–36.99 MiB**；旧 spill **376.91–377.38 MiB**、
新 spill **36.82–37.25 MiB**。新旧范围明显分开，可复现的下降来自
RuntimeTrace 表示。**新版 spill RSS 仍略高于新版 memory，不能以本轮
结果宣称 spill 已降低真实构建峰值。** 图只有约 12,000 节点，卸载的容量
不足以抵消这档工作负载的其他成本；后续需要完整工作集与更有代表性的输入。

| N | 新 memory Stage ms | 新 spill Stage ms | 新 memory 首查 ms | 新 spill 首查 ms |
| --- | --- | --- | --- | --- |
| 128 | 0.494 | 1.045 | 0.046 | 0.148 |
| 512 | 1.623 | 2.256 | 0.190 | 0.263 |
| 1024 | 1.787 | 6.437 | 0.225 | 0.579 |
| 2048 | 3.826 | 11.149 | 0.316 | 0.753 |

Stage 时间取仅构建进程，首查时间取独立的 build+query 进程，两列不能直接
相加后充当某个实际样本。最大档旧 memory/spill Stage 为 80.805/81.862 ms；
新版对应整个构建子进程墙钟为 16.003/26.497 ms。存在频率和调度噪声，
完整分布见 JSON，不据此推广到一般程序。最大档新版 build+query 整进程
RSS 为 memory **37.26 MiB**、spill **37.56 MiB**，仍非隔离的查询峰值。

spill 的节点封块和按需 IO 如下；所有正式样本 build CAS 重读均为 0，
spill 的兼容图 materialized 均为 0：

| N | 图节点 | 临时文件 | 文件总字节 | 首查 CAS 读取 | 首查 payload 字节 | 累计释放活动容量 |
| --- | --- | --- | --- | --- | --- | --- |
| 128 | 789 | 1 | 21,882 | 1 | 21,833 | 40,960 |
| 512 | 3,093 | 4 | 85,860 | 2 | 52,522 | 122,040 |
| 1024 | 6,165 | 7 | 171,086 | 5 | 131,671 | 244,256 |
| 2048 | 12,309 | 14 | 341,616 | 8 | 210,011 | 467,376 |

累计释放容量可多次计算复用后的同一活动区，不是净 RSS 下降量。最大档
builder peak-owned 为 45,456 字节，目录/摘要容量为 2,048/24 字节，均不含
其他元数据与临时编码缓冲；这些小计不构成完整工作集。

最大档独立 census 的 memory/spill 均有 **8,419,374** 个逻辑路径步骤，
实际唯一 Step 为 **8,202**，Step/堆字符串容量小计 **393,696** 字节。
模块可达 HIR 表达式为 12,303 个，路径句柄为 8,211 个；两种模式相同。
Provenance 有 12,310 个站点、4 个根，此输入没有稀疏 StageDecision 条目；
不代表已经覆盖大量决策、特化参数或契约的保留成本。

## 验证与剩余门槛

新增单测覆盖分支共享、拼接与自拼接、移动/恢复、线性唯一 Step 数、
深链释放，以及真实 Stage 512 步失败诊断完整顺序和早期绑定不被修改。
原有嵌套调用/热缓存诊断、聚合投影、静态初始化、递归、来源解释、MIR/
LLVM 残留执行和辅助失败回归同时验证。

验证结果：Debug **338/338 CTest**，含 **392/392 lit**；GCC 与
ASan/UBSan 各 **337/337 非 lit CTest**、相关 CLI 各 **13/13 lit**；
Release 相关 **75/75 CTest**；文档检查 **35 文件**、C++ 格式和
whitespace 检查均通过。

C4b3b 继续计量/处理站点、根、决策、weak HIR 映射、特化参数、去重表和
Analyzer 保留项；补齐真实进程崩溃、额度耗尽、孤立任务目录处置和总 IO。
只有可复现的 spill 构建峰值下降以及这些验收均成立，才完成完整 C4b。

后续 [C4b3b](provenance-working-set-c4b3b.md) 已完成其余工作集、真实崩溃
和目录维护验收，在较大真实图上确认 spill 相对 memory 的构建峰值收益。
完整 C4b 实验范围完成；本页测量和结论保持为 C4b3a 当时的数据。
