# S2：缓存成本与使用决策

小型板级配置继续使用默认的 `--stage-cache=off` 和 memory 证据模式。
本轮只有较昂贵的封闭数组显示了明确热读收益；大量小查询的文件 IO
会超过省下的求值工作。大图可显式选择 spill，用时间和写入成本换取内存。

这组结果用于确定 CH32V307 Demo 的构建默认值：先验证 Comptime 配置和
Runtime 设备访问，再按实际负载决定是否启用持久缓存。

## 用同一构建重跑成本账本

复现本轮环境时，在[开发指南](development.md)的固定 CI 镜像内执行。
从仓库根目录配置一个独立 Release 构建，完成构建后顺序采样：

```sh
cmake --preset release -B build/s2-release
cmake --build build/s2-release -j4 --target pagosc pagos_snapshot_bench \
  pagos_function_evidence_bench pagos_query_task_bench pagos_stage_spill_bench
python3 scripts/benchmark_costs.py --build-dir build/s2-release \
  --output-dir build/benchmarks/s2-new-run --date 2026-11-01
```

输出目录必须是新的或空目录，以免覆盖旧报告。`--smoke` 用较小的既有
语料验证采集路径；正式配置默认预热 2 次、测量 7 次。既有 benchmark
命令和默认构建路径继续可用，新增 `--target`、`--build-dir` 或 `--binary`
选项可将各工具指向同一构建。采样期间停止其他构建和测试。

本轮于 2026-11-01 使用本地提交 `6bb6d74`，采样开始时源码无未提交修改。
固定 CI 镜像提供 Clang/LLVM **22.1.8**、CMake **4.4.3**、Python **3.14.7**；
主机为 AMD Ryzen AI 9 HX 470，Linux **7.3.0-5-cachyos**，工作文件系统为
**btrfs**。容器限制为 4 个 CPU 的配额，不固定核心或频率。

CLI 明确选择 RV32，LLVM 解析为 `riscv32-unknown-unknown-elf`、
`generic-rv32` 和 `e-m:e-p:32:32-i64:64-n32-S128`。证据探针使用自己的
固定 RV32 语义 context（`e-p:32:32`），不发射机器码。比较只在同一
工具、输入及预算内部进行；不将不同探针的时钟拼成编译流水线总时间。

[总账 ledger.json](../benchmarks/results/s2-2026-11-01/ledger.json)记录命令、
源码/工具/二进制/配置身份、目标、机器、文件系统和各类预算。
六份原始报告共 **138 组、966 个正式样本**，另有预热、seed、语义验证
和 14 个独立 census 样本：

## 计算复用：减少求值不一定缩短编译

下表为 `check` 的进程 wall 中位数，括号为 min–max，单位 ms。
三种模式的 Stage 输出、逻辑计费和各自 MIR/LLVM 输出指纹一致。

| 负载 | off | cold | hot |
| --- | --- | --- | --- |
| 8192 元素封闭生成器 | 13.938（12.826–14.907） | 16.053（14.967–17.073） | 9.680（8.678–10.774） |
| 1024 个小标量特化 | 16.117（10.952–17.176） | 194.907（189.646–204.139） | 39.324（37.005–60.301） |
| CRC-32 | 20.266（17.104–26.593） | 26.661（24.485–34.067） | 26.738（23.485–36.158） |
| 板级配置 | 9.674（6.626–11.782） | 8.664（7.542–13.034） | 11.770（6.467–11.913） |

封闭生成器的热读跳过 1 次函数体，整体中位数降低约 **30.6%**，本轮
样本范围分离。求值阶段从约 4.033 ms 降至 0，读取/验证各有成本。
逻辑 Fuel 仍为 **65,548**，构造仍为 **8192 成员 / 32,768 字节**。

小特化的热读跳过全部 **1024** 次函数体，但只省下约 0.428 ms 的纯求值。
热读的 query/read 阶段中位数分别约 **6.124/21.184 ms**；冷发布约
**162.175 ms**，最终产生 **6145 个文件、1,773,758 字节**。
相比之下，大数组只有 **8 个文件、68,194 字节**。批量小对象的键、
manifest、校验和文件访问是当前实质成本。

CRC 的递归调用不属于可持久复用的外层子集，三种模式都没有磁盘命中；
启用缓存仍有依赖身份和准入检查开销。
聚合负载同样没有命中或缓存文件，但其 off/cold/hot 中位数也会波动。
因此不能把模式名称或偶然较短的时间当作缓存收益。板级配置的范围重叠，
不值得为这几次算术计算默认打开持久缓存。

小残留模板的 off/cold/hot 分别为 **11.790/11.730/11.758 ms**，范围重叠；
热读确实跳过函数体，整体仍受启动、身份和证据恢复影响。

## 编辑：位置可复用，整模块校验使无关编辑也失效

每个样本先在计时之外建立原始缓存，再执行一次编辑后的 read-write
编译。输出和逻辑计费都与当前编辑版本的 uncached 编译对照。

| 编辑 | 命中 / 函数体分析 | 首次编辑后编译 ms 中位数 | 缓存总字节变化 |
| --- | --- | --- | --- |
| 不变 | 1 / 0 | 10.625 | 2022 → 2022 |
| 前置注释/换行 | 1 / 0 | 7.724 | 2022 → 2022 |
| 新增无关函数 | 0 / 1 | 9.607 | 2022 → 3764 |
| 修改函数计算 | 0 / 1 | 9.585 | 2022 → 4044 |
| 板级版本 1 → 2 | 0 / 3 | 8.601 | 3945 → 7911 |

无关函数仍改变 verified inputs 的整模块指纹；板级版本变化同样使两个
纯分频函数重新求值和发布。当前行为优先保证保守失效，旧 CAS/manifest
仍保留。表中时间范围均见原始报告，不能据这些小样本排序编辑性能。
这也说明后续细化依赖应同时衡量保留文件和重新发布成本。

## 证据构建与读取：按需展开节省读取，spill 用时间换内存

模块快照的 1024 步探针，Stage/编码/校验打开/恢复/单次查询中位数分别为
**1.505/5.422/0.473/1.002/0.168 ms**。在 512 步 CLI 用例中，直接分析与
完整快照读取分别为 **13.833/16.958 ms**，范围重叠；跳过 Stage 后仍有
源码检查、身份验证、读取和图恢复工作。快照的两个 CAS 文件分别为
**16,663 / 178,265 字节**。

两个函数、每个 1024 步的按需读取，只加载相关的 **2 个冷对象 / 444,028
payload 字节**；整图恢复加载 **3 个 / 885,661 字节**。首查连同热元数据
加载和准备的中位数为 **4.121 / 7.358 ms**；不能仅用恢复后的 query
计时比较端到端成本。进程内重复查询不再读取冷对象，中位数为
**0.150 / 0.140 ms**。两种方式得到相同的来源签名。

大图 spill 的结果更明确：131,975 个节点的构建峰值中位数从
**191.52 MiB** 降到 **182.63 MiB**，减少约 **8.90 MiB / 4.65%**。
memory 的范围为 **187.86–192.54 MiB**，spill 为 **181.45–184.77 MiB**。
Stage 中位数从 **116.451 ms** 增到 **158.571 ms**，增加约 **36.2%**。
小图、契约密集或数组参数负载没有一致的净内存收益。

最大 spill 用例生成 **162 个 CAS 文件和 1 个 marker**，合计
**4,099,377 字节**；首个正式 build 样本的 rchar/wchar 为
**5,668,366 / 4,099,377**，内核 write_bytes 为 **4,734,976**，read_bytes
为 **0**。后者反映热页缓存下的内核记账；读取校验、文件元数据和后续
清理仍然存在。默认保持 memory，内存确有压力的大图显式启用 spill。

## 查询任务：暂停后释放容量，恢复与续跑仍需付费

以下取 2049 个输入的 wide 用例。时间是内部保存/恢复时钟的中位数，
容量是首个正式样本的任务 owned bytes，排除图/view、目录及分配器开销。

| 模式/切点 | 保存 / 恢复 ms | 保存前 → 保存后 owned 字节 | 运行结束目录字节 / 文件 |
| --- | --- | --- | --- |
| 原生 memory/frontier | 0.424 / 4.056 | 32,780 → 32,780 | 9066 / 6 |
| 原生 paged/frontier | 0.523 / 3.955 | 97,920 → 0 | 140,682 / 15 |
| 拓扑 resident/formula | 0.700 / 4.327 | 250,804 → 250,804 | 45,654 / 4 |
| 拓扑 segmented/formula | 0.829 / 4.307 | 250,804 → 0 | 46,615 / 10 |

原生分页的续跑为 **2.563 ms**，memory 为 **0.202 ms**；原生任务的
读请求为 **63 / 15**，写请求为 **13 / 4**。固定缓冲使小任务的分页 owned
容量反而更大。拓扑公式切点的 segmented 保存增加文件，但暂停后确实
释放任务容器；恢复中位数与 resident 接近。

这些模式恢复后保持同一来源/拓扑结果和逻辑工作计数，Stage runs 为 0。
目录大小包含旧对象、head、marker 及续跑期间新增对象，不能当作单个
checkpoint 的字节数。使用分页或分段保存是容量与可续接性的选择，不能
仅凭保存后 owned=0 推断进程 RSS 已降到零。

## 纯重放：执行范围小，读取和呈现仍占成本

标量 3 节点重放的 CLI 中位数为 **11.769 ms**，结果核验消耗 **4 Fuel**。
完整详情输出 **1378 字节**，只保留核验结果时为 **848 字节**，Fuel 相同。

| 生成器 | 选中元素 | 完整详情 wall ms 中位数 | bounds / element 节点 | Fuel | JSON 字节 |
| --- | --- | --- | --- | --- | --- |
| 4 元素 | 0 | 11.792 | 2 / 5 | 10 | 2310 |
| 4 元素 | 3 | 11.788 | 2 / 5 | 10 | 2310 |
| 4096 元素 | 0 | 10.824 | 2 / 5 | 10 | 2316 |
| 4096 元素 | 4095 | 10.745 | 2 / 5 | 10 | 2334 |

每个结果都用独立算术期望值核验，并在 `--max-fuel=0` 下保持 stage_runs=0。
选择末元素没有增加元素执行工作；4096 元素的记录仍整体读取、解码和
校验。两种数组的缓存目录分别为 **2861 / 35,597 字节**。小 wall 差异处于
波动范围内，不能据表格声称数组越大重放越快或端到端开销恒定。

只取核验结果会把生成器 detail_records 从 5 降到 0，Fuel 仍为 10，
JSON 降至约 **1320–1335 字节**。执行 payload 的 output_bytes 与实际
JSON/换行字节是两个口径，原始报告同时保留。

冷记录标量、4 元素和 4096 元素时，普通 value 模式和显式要求 replay
能力均已发布配方；两者文件数量和字节数相同。此次源码本来就在可记录
子集内，不能把两种选项的 wall 差异解释成证据记录的独立成本。要核算
整个记录链，应对照 off：其余两种都会承担值、资源、描述和 manifest。

## 读数口径与 S3 接续

CLI wall 包含启动、输出捕获和 1 ms 轮询。`--cache-stats` 的函数体求值
时钟可因嵌套调用重叠，不与 wall 等价。wait4 RSS 是整子进程高水位，可能
受 fork/pre-exec 的父进程 RSS 下限影响；小 CLI 仅描述该值，不用它证明
内存收益。spill 构建比较使用探针在本次 exec 后记录的 VmHWM。

cold 指每个样本的应用目录为空，OS 页缓存未清空。input_blocks /
output_blocks 是 wait4 的文件系统块操作计数，包含 stdout/stderr 临时文件；
spill 的 proc IO 在输出/析构前采样，任务的 read/write requests 是逻辑
存储调用，三者不能混算成物理磁盘吞吐。清空 cold 目录与建立 hot seed
位于计时之外；工作集探针另检验临时 spill 生命周期回收。

[board-profile.pgs](../benchmarks/board-profile.pgs)以显式 bus/baud 和板级
版本产生常量，Runtime 保留 `uart_exchange` 调用。版本 1/2 的残留调用
参数分别为 **625 / 313**，分支已在 Comptime 选定。该工作负载测的是 S3
配置路径；芯片时钟树、寄存器编码和物理串口在 S3 对照实际板卡接入。
届时沿用本轮命令加入实际固件输入，保留 off/cold/hot 的行为与预算对照。

S2 不改变 S1 协议、缓存准入或默认开关。下一步按计划进行 C 参考固件、
Pagos 配置计算和原生轮询 UART 的实机切片。
