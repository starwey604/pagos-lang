# Provenance 原型与选型实验

本实验比较三种证据表示，初步选择追加式整数 ID 图作为后续接入的基础。
选择性去重适用于重复证据；调用来源摘要和批量查询缓存仍需进一步实验。

初始实验在提交 `dde612d` 中与 `StageAnalyzer` 分开，未链接到 `pagosc`。
后续已拆分构建与只读接口，并[接入真实 Stage](provenance-analysis.md)。下面的
测量表仍记录独立原型的结果，不是接入后的编译成本。基准输入是合成的证据
构造事件，不是 `.pgs` 程序；测量结果不能直接当作整个编译器的提速比例。

## 三种表示

| 方案 | 存储 | 来源查询能力 |
| --- | --- | --- |
| `paths` | 实际 `hir::RuntimeTrace`，复制字符串路径并保留第一来源 | 单条已有路径 |
| `append` | 32 位 ID、追加式节点池与边池 | 完整直接依赖与按需遍历 |
| `intern` | 追加式图加选择性结构去重 | 与 `append` 相同 |

`paths` 是表示基线，模拟第一来源选择、路径复制和符号参数替换，没有模拟
整个 HIR 或编译器。递归引用以保守的合成来源表示；它不能回答完整来源集合。
两种图方案的来源数量、覆盖标记和校验值在每组测量中进行交叉检查。

## 存储与语义关系

[实验接口](../include/pagos/stage/provenance_graph.h)使用 `NodeId` 和
`SummaryId`。节点保存规则、实验位置编号、边区间、参数槽或摘要引用。
在本次 x86-64 工具链中，节点为 24 字节，边为 8 字节，`RuntimeTrace`
为 88 字节；HIR 的可选 trace 字段另有占用。

独立实验使用合成的 `SiteId`，真实源码位置表、类型和常量引用、目标配置与
构建环境快照未纳入独立实验。真实源码位置表见上述接入说明。ID 只在所属图内
有效，不能作为跨修订身份。节点 ID 在增长时保持稳定；`node()` 和 `edges()`
返回的构建期视图可能因增长失效。存储统一拥有节点与边，摘要发布一次，
不通过拥有指针形成递归环。

关系区分数据、控制、契约、效果与初始化证据。值来源查询不穿过效果或显式
边界的初始化关系；效果查询仍能观察产生结果的初始化工作。

例如，记录中有一个已知字段和一个未知字段，投影只选择对应成员的值证据。
别名与求值序列可以保持成员精度，同时通过初始化关系保留整个构造的效果。
显式 Runtime 边界不会被投影穿透。这个表示不增加相同分支常量的收敛规则。

`intern` 只处理调用方标记为候选的 `Literal`、`Strict`、`Aggregate` 和
`Parameter`。键保留位置、参数作用域、负载及有序依赖，并对哈希碰撞进行
完整比较。来源、效果、调用和普通使用位置保持独立，避免把证据共享解释成
合并执行。

## 调用与查询

函数摘要记录符号参数。调用保存实参 ID；查询时建立上下文，参数在所属函数
作用域中绑定，并在调用方上下文中继续查询实际来源。

例如，共享同一个 `scale` 摘要的 `scale(4, a)` 和 `scale(4, b)`，分别得到
`a` 和 `b` 的来源。摘要内的读取或效果也按调用上下文区分。查询结果拥有调用
上下文表，工具可以沿表中的父关系解释调用位置。

查询使用迭代 BFS，以 `(节点 ID, 上下文 ID)` 去重。完整查询收集全部可达来源；
短路径查询只生成一条 BFS 见证，不枚举所有路径。遍历成本取决于展开后的
节点和边，稳定输出排序另外需要 `O(K log K)`，其中 `K` 是来源数量。

状态预算耗尽或参数未绑定时，结果标记为不完整。初始实验允许查询尚未发布的
摘要；现在的冻结接口要求全部摘要发布，中止分析使用 `Incomplete` 规则。
`complete`
表示相对于已记录证据图的来源集合覆盖程度，因此找到一条见证后提前结束
也不能声称集合完整。这个标记不参与语言 Stage 判断。

有限的 `SummaryRef` 环通过已访问状态终止，并能收集环中记录的来源。
继续建立调用上下文的递归则明确截断，返回部分结果。本轮没有实现递归参数
来源的 SCC 不动点求解，也没有证明程序终止。

## 工作负载与测量方法

| 用例 | 关注的问题 |
| --- | --- |
| `chain` | 长别名链的路径复制与共享 |
| `unique` | 每条候选证据都不同，去重索引没有命中 |
| `fan-in` | 平衡合并树中的全部独立来源 |
| `repeated` | 相同位置、相同输入的纯证据重复构造 |
| `calls` | 多次调用共享一个 64 层使用链的符号摘要 |
| `aggregate` | 一半成员已知、一半未知的逐成员投影 |
| `recursive` | 有限摘要引用环的构建与完整来源遍历 |

查询分为仅构建、单条见证、完整来源和批量冷见证。批量查询分别查询每个绑定，
没有跨查询缓存。`fan-in` 的绑定是叶子，`recursive` 的绑定是环入口，因而
不同用例的批量时间不能直接横向比较。

构建和查询时间由 C++ 阶段时钟测量，排除进程启动与最终 JSON 格式化。
每个模式在独立进程运行，GNU time 记录该进程峰值 RSS。池容量包含预留空间，
排除分配器开销、位置表和查询临时表，也不等于实际驻留内存。

工具还分别计数构建和查询阶段的 C++ `new`/`new[]` 请求。LLVM 容器直接使用
`malloc` 的分配不在该计数内；累计请求字节不表示存活内存。调用参数和字段
投影使用内联小容器，避免通常 arity 下的逐次堆分配。

路径基线的查询读取已有 trace，图查询需要遍历并生成见证。两者不输出路径
文字，而且基线不提供完整来源，因此查询时间不能直接作为同等能力排名。

## 复现实验

在 LLVM 22 环境中构建 Release：

```sh
cmake --preset release
cmake --build --preset release --target pagos_provenance_bench
python3 scripts/benchmark_provenance.py \
  --output build/benchmarks/provenance.json
```

图方案的较大规模实验：

```sh
python3 scripts/benchmark_provenance.py \
  --storages append intern --cases chain unique fan-in repeated \
  --sizes 8192 32768 131072 --queries build sources \
  --output build/benchmarks/provenance-large.json
```

默认每组预热两次、正式采样七次，反转方案执行顺序。报告记录全部样本、
时间范围、RSS、池容量、分配计数、访问状态、来源覆盖、机器、工具版本、
二进制及源码哈希。测量时停止并行构建和测试。原始 JSON 保留在忽略的
`build/` 内；此文保存解释与结论，不设性能通过阈值。

## 本次测量

本次使用 Intel Core 5 315、Clang/LLVM 22.1.8 和 Release 配置，在固定的
`pagos-ci` 容器中测量。普通实验有 252 组，大规模实验有 48 组，合计 2100 次
正式采样及 600 次预热。下表时间为七次正式采样的中位数；构建时间取仅构建
模式，完整查询时间取来源枚举模式。`size` 表示工作负载输入规模，各用例的
实际节点数量不同。

### 存储与构建

`size = 2048`，池容量单位为 KiB，构建时间单位为毫秒：

| 用例 | 表示 | 构建 ms | 池容量 KiB | C++ 分配次数 |
| --- | --- | ---: | ---: | ---: |
| `chain` | `paths` | 37.495 | 131520.0 | 4110 |
| `chain` | `append` | 0.094 | 112.0 | 25 |
| `unique` | `paths` | 54.088 | 131520.0 | 4110 |
| `unique` | `append` | 0.099 | 128.0 | 25 |
| `unique` | `intern` | 0.327 | 208.0 | 36 |
| `repeated` | `paths` | 0.768 | 1160.2 | 8225 |
| `repeated` | `append` | 0.195 | 288.0 | 30 |
| `repeated` | `intern` | 0.149 | 129.1 | 29 |
| `calls` | `paths` | 4.813 | 9422.2 | 10402 |
| `calls` | `append` | 0.190 | 225.0 | 31 |
| `aggregate` | `paths` | 0.575 | 880.2 | 3120 |
| `aggregate` | `append` | 0.218 | 256.0 | 20 |

长链中保存每个前缀路径，会形成二次增长；图只保存各节点的直接关系。
`chain` 的路径池约为 128.4 MiB，图池约为 112 KiB。同组仅构建进程的峰值
RSS 分别约为 104.7 MiB 和 29.7 MiB；预留容量与 RSS 并不相等。进程和 LLVM
共享库本身已占用内存，因此小图之间的 RSS 差异不足以判断证据占用。

选择性去重没有统一收益。`unique` 零命中，索引让容量增加 62.5%，构建时间
约为追加式图的 3.3 倍。`repeated` 有 2047 次命中，容量减少约 55%，构建和
完整查询均受益。其他未标记候选的规则不会进入去重索引。原型的相同位置、
相同输入重复构造是有意设置的条件，接入时还需测量真实编译是否存在这种重复。

调用和投影的低分配次数来自共享摘要、节点池以及临时内联容器；它们不表示
LLVM 容器完全没有分配。路径基线使用短合成位置名，通常落入字符串内联空间，
池容量没有计入哈希表桶和额外字符缓冲，不能外推为真实源码名称的精确成本。

### 来源覆盖与查询成本

`size = 2048` 的完整来源查询：

| 用例 | `paths` 返回 | `append` 返回 | 图覆盖完整 | 图查询 ms |
| --- | ---: | ---: | --- | ---: |
| `fan-in` | 1 | 2048 | 是 | 0.329 |
| `aggregate` | 1 | 1024 | 是 | 0.311 |
| `calls` | 1 | 2048 | 是 | 12.864 |
| `recursive` | 1 个合成来源 | 2048 | 是 | 0.517 |

`intern` 在这些查询中返回相同事实。路径基线读出已有 trace 的时间不能与
图的完整来源枚举直接排名；表中的覆盖差异才是语义能力的区别。

共享存储并不意味着共享查询工作。`calls` 只有一个 64 层摘要，但完整查询
仍访问 137217 个上下文状态，建立 2048 个调用上下文；225 KiB 的池没有消除
12.864 ms 的展开成本。逐个调用查询的批量总时间为 2.749 ms，访问状态数量
基本相同，工作集较小。后续应比较参数来源摘要与详细推导的按需展开。

`chain` 的一次完整查询为 0.171 ms；分别查询 2048 个绑定的冷见证却需要
51.897 ms，访问 2100224 个状态。512、1024、2048 个绑定的访问次数分别为
131840、525824、2100224，清楚显示重复前缀遍历的二次增长。后续需要批量
拓扑输出、轻量见证索引或有界查询缓存，而不能为每个节点保存全部来源集合。

### 较大规模

`size = 131072`，时间单位为毫秒，池容量单位为 MiB：

| 用例 | 表示 | 构建 ms | 池容量 MiB | 完整查询 ms |
| --- | --- | ---: | ---: | ---: |
| `chain` | `append` | 5.879 | 7.000 | 11.978 |
| `chain` | `intern` | 5.767 | 7.000 | 11.670 |
| `unique` | `append` | 5.915 | 8.000 | 12.516 |
| `unique` | `intern` | 20.308 | 13.000 | 9.811 |
| `fan-in` | `append` | 7.801 | 8.000 | 23.915 |
| `fan-in` | `intern` | 7.894 | 8.000 | 23.361 |
| `repeated` | `append` | 13.192 | 18.000 | 19.217 |
| `repeated` | `intern` | 10.227 | 8.001 | 10.725 |

这些完整查询均通过覆盖及来源数量检查。追加式长链在 8192、32768、131072
规模的池容量分别为 0.438、1.750、7.000 MiB，验证了直接关系存储的线性增长。
较大规模继续出现去重零命中的成本和高重复时的收益，支持默认追加、按证据
启用去重的选择。

查询临时内存也需要预算。例如 `fan-in` 的追加式池为 8 MiB，仅构建的进程
峰值 RSS 约为 35.8 MiB，包含完整查询的进程则约为 55.9 MiB。节点池容量不能
代替整个分析过程的内存预算。本轮的原始样本、波动范围与哈希记录保存在
`build/benchmarks/provenance.json` 和 `build/benchmarks/provenance-large.json`；
上述结论来自独立证据实验，尚未测量编译器接入后的端到端收益。

## 后续迭代顺序

1. 已以 `append` 接入真实 Stage，拆分 Builder 与 FrozenGraph，并明确位置表
   和快照所有权。继续保留旧诊断视图作行为对照，测量真实编译的新增成本。
2. 为常用诊断比较轻量见证索引和有界查询缓存。批量输出共享拓扑及根 ID，
   详细路径按结果展开，减少重复遍历。
3. 为高频特化增加按需的参数来源摘要，分别测量来源枚举与完整推导展开。
   摘要既要区分参数来源，也要保留每次调用的内部来源及效果身份。
4. 在确实存在重复证据的边界启用去重；比较哈希索引、池容量和查询收益。
   大型生成器的区间摘要、分块池、反向索引与跨修订缓存另行实验。
5. 对递归参数映射建立有限摘要域，比较 SCC 内的单调传播与解释预算。
   部分解释继续携带覆盖标记。

后续迭代继续使用 `.pgs` 正反例和端到端编译测量。原型得到的空来源集合
不会被用作新的 Comptime 判定规则。

投影、边界、值与效果分离、嵌套调用、调用来源替换、上下文身份、递归、预算、

格式、clang-tidy、文档链接、Python 语法与差异空白检查一并验证。
