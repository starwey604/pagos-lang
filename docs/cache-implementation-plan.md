# Pagos 缓存实现迭代计划

状态：C1a/C1b 已实现，C2a–C3b 待实施。探索基线为 `llvm` 分支 `5a01805`，
计划日期为 2026-10-11，C1a/C1b 完成日期为 2026-10-12。
设计约束以 [Cache Architecture RFC](cache-architecture-rfc.md) 为准；
本计划将 C1–C3 拆成可独立交付的工作，C4 根据结果另行规划。
C1a 的接口、格式和验证见[实现记录](cache-identity-c1a.md)。
C1b 的发布、错误与维护边界见[文件存储实现记录](cache-store-c1b.md)。

## 目标与执行顺序

先建立跨进程稳定身份和可恢复存储，再验证真正跳过求值，最后恢复复杂
证据与残留模板。默认使用文件系统 + CAS，模块 Provenance 使用专用
分段二进制格式。每轮保持 Stage、诊断、残留行为及会话内预算规则。

| 轮次 | 范围 | 主要产物 | 完成后可验证什么 |
| --- | --- | --- | --- |
| C1a | 稳定身份与规范键 | 键/类型/值编码、SourceAnchor | 相同语义跨进程同键，Stage 与目标差异分开 |
| C1b | 文件存储与 manifest | 文件 CacheIndex、CAS、发布协议 | 可恢复查询对象，损坏与 IO 失败安全未命中 |
| C2a | 纯标量缓存 | Analyzer 接入、资源协议、实验控制与遥测 | 第二次进程真实跳过纯函数体求值 |
| C2b | 封闭数组生成 | 数组负载、构造资源记录与测量 | 热缓存复用表内容，Runtime 索引与预算正确 |
| C3a | 模块 Provenance 快照 | section 编码/读取、位置映射、恢复实验 | 恢复后的值/效果/决策查询与原图相同 |
| C3b | 符号残留模板 | 参数重绑定、关联证据、MIR 验证 | 共享定义但各次调用来源和效果独立 |

顺序为 C1a → C1b → C2a → C2b → C3a → C3b。每轮可以拆成小提交，
不能将纯编码 round-trip 宣称为编译器已经复用计算。未支持的程序继续走
原有分析路径，不因缓存准入限制而变成语言错误。
近期优先执行 C1a 至 C2b，并在数组复用测量后复核 C3 的范围。P1 的有限
Comptime 理由无需等待 C3/C4 全部完成；新增证据规则需同步更新格式版本
和准入/恢复测试，尚不能恢复的结果继续回退。

## C1a：稳定身份、规范编码与位置 Anchor

本轮先构建最小协议，不读写磁盘、不修改 Analyzer 的求值路径。

实施内容：

1. 在 `include/pagos/cache/` 与 `lib/cache/` 建立对象种类、协议版本、
   稳定摘要及有界编码/解码设施。公共接口只用 Pagos 和标准 C++ 类型；
   若复用 LLVM Support 的哈希工具，将其留在私有实现中。
2. Stage 适配器生成 StableDefinitionId、定义/整模块语义指纹与规范
   TypedStageArguments。初期覆盖标量和固定长度标量数组；记录/指针
   返回明确的暂不支持，不构造不完整的可命中键。
3. 定义/模块指纹排除位置和空白，保留解析引用、类型、运算结构、契约及
   影响预算的结构。定义路径与内容摘要分开，避免把 AST 地址或 NodeId
   带入跨进程身份。
4. 建立定义内结构位置的 SourceAnchor 及当前 Anchor-to-Span 映射。
   只保证纯空白/注释变更下的映射；一般结构编辑允许保守失效。
5. 由 driver 提供已解析的目标描述与编译器兼容身份，Stage 只消费不可变
   QueryContext，不依赖 codegen 的 LLVM 类型或自行推测 host 布局。

接入参考：[类型和值](../include/pagos/value.h)、
[语义类型](../include/pagos/sema/type.h)、
[目标配置](../include/pagos/codegen/target.h)及
[StageAnalyzer](../include/pagos/stage/stage_analyzer.h)。
已增加 [cache_key_test.cpp](../tests/unit/cache_key_test.cpp)、
[cache_codec_test.cpp](../tests/unit/cache_codec_test.cpp)及
[跨进程测试](../tests/cache_identity_process.py)。不要求一次为所有未来
类型设计完整 codec。

验收：不同进程/地址分配下同键；空白和注释修改同语义指纹、当前位置正确；
Runtime 边界、参数顺序、静态值、宽度/符号、`usize`、目标或预算协议变化
不能错误命中；`1 + 1` 与 `2` 不因同值消除资源结构差异。解码覆盖未知
版本、截断、非法长度及溢出。构建既有程序的输出不变。

本轮完成条件是可用于下一轮的稳定键与标量/数组编码，不是新增永久 ABI。
当前 format/query/budget 协议版本均为 1；Analyzer 只接收只读上下文，
求值路径未接入这些协议。C1a 不判定函数纯度，不恢复资源或依赖，也不读写
磁盘。后续 manifest 必须另行记录、验证保守整模块依赖。

## C1b：文件 CacheIndex、CAS 与故障恢复

依赖 C1a 的规范对象与摘要，但仍不跳过语义求值。

实施内容：

1. 扩展 C1a 已建立的 `pagos_cache` 库，负责对象读写和分片 manifest 查找；
   Stage 的编码/依赖判断作为适配器，存储库不调用 StageAnalyzer。
2. 实现 `queries/`、`objects/`、`tmp/` 的发布协议：先不可变对象，后
   manifest；使用同文件系统的唯一临时文件，不原地修改已发布对象。
3. 校验候选规范键、版本、对象种类、长度与内容摘要；依赖适用性及语义
   准入留给调用方。缺对象/坏索引/不可写均以明确的未命中原因返回。
4. 同内容并发发布可复用对象；同一已验证输入得到不同语义结果时报告内部
   确定性问题，不静默采用最后写入者。旧输入版本的候选失效不算冲突。
5. 首轮提供完整对象读取，不启用 mmap、压缩、在线 GC 或数据库。允许
   崩溃遗留临时文件/孤儿，维护清理先使用互斥窗口。

已增加 [cache_store_test.cpp](../tests/unit/cache_store_test.cpp)和
[独立进程测试](../tests/cache_store_process.py)，验证发布、重新打开、
真实中断与并发，而不只在同一对象实例上 round-trip。

验收：合法对象可恢复；在临时写入、对象发布后、manifest 发布前中断都
不会命中半个结果；并发同内容发布正确；截断、非法引用、目录被删除、
写入失败与容量限制安全回退。磁盘满等难以稳定复现的路径使用 IO 故障
注入覆盖，真实文件系统测试同时验证正常发布行为。

本轮完成后仍不能宣称编译时间改善；它提供 C2 的真实磁盘访问基础。
当前 store 格式版本为 1，以查询键和已验证输入指纹定位各代 manifest；
旧依赖代际独立保留。FileStore 不替 Stage 验证纯度、依赖适用性或资源。
首版没有在线 GC/清理命令，离线维护须停止所有读写。具体 API、冲突标记
写入失败及 flush/断电边界见上述实现记录。

## C2a：纯叶函数标量缓存的第一个垂直切片

依赖 C1a/C1b。接到 `analyze_call` 的会话内 miss 路径，保留原有实参分析、
类型检查、会话内缓存优先级及最终 HIR/MIR 流程。

第一批准入为全 Comptime 标量参数、标量结果的纯叶函数，例如 `square`。
先限制为能恢复当前解释的简单表达式体；不包含普通函数调用、递归、
聚合/指针/全局引用、局部契约或需要尚未实现的决策证据。
实参表达式自身可以携带残留工作，只要查询使用的值已知、工作仍由当前
调用方保留；函数体缓存负载不能包含这些工作。

实施内容：

1. 收集并保存键、保守整模块依赖、类型/常量、SourceAnchor 与 ResourceRecipe。
   前端仍每次运行，缓存只复用准入的函数体分析结果。
2. 资源记录从正常 Analyzer 的检查点产生。第一版精确覆盖进入深度、
   特化计数与函数体 Fuel；调用表达式和实参已付成本不纳入记录。
3. 在状态副本上验证成本及位置，成功后一次提交恢复结果、统计和当前会话
   memoization；预算不足/恢复失败时丢弃副本，从原 miss 路径继续分析。
4. 通过现有 Recorder 记录恢复 HIR；原始结果无法按当前位置/解释要求重建
   时拒绝持久化。存储成功不代表任何相同表面值都可准入。
5. 提供实验性关闭/读写/只读模式、明确缓存目录和独立遥测。选项在本轮
   定稿并写入开发文档；默认关闭，正常诊断和 explain 输出不混入磁盘统计。
   启用目录加入版本管理忽略规则。

拟增加 `stage_cache_test.cpp` 与 `tests/lit/cache/`。lit 必须运行两次独立
编译进程，使用专用临时目录；报告磁盘命中及实际函数体求值是否被跳过。

验收：关闭、冷、热三个模式的 Stage、结果、逻辑 AnalysisStats、当前
诊断和残留输出一致；同会话第二次调用保留已有命中计费规则；预热后降低
Fuel/深度/特化数，错误与关闭模式一致且未重复扣费；已知实参附带工作时
仍保留源顺序和执行次数。修改函数、Stage、参数、目标、依赖或对象格式
正确失效，纯空白修改能够命中并重映射位置。不准入程序正常回退。

本轮必须证明至少一个实际计算被跨进程复用，不要求小标量总体一定加速。

## C2b：封闭数组生成与性能证据

依赖 C2a 的成功路径和预算回退协议。加入固定长度、标量元素的纯数组
返回与生成器；首批为 `table()` 中直接算术生成，不调用其他普通函数。
嵌套普通特化、递归、记录、混合数组及顶层独立生成器查询继续延期。

实施内容：

1. 恢复数组类型、元素顺序与多宽度常量；生成器形状、元素数量和负载长度
   在解码前检查。不要在本轮顺带引入常量池或改变已有 Constant 所有权。
2. ResourceRecipe 记录边界计算、生成迭代 Fuel 及构造保留的原始顺序。
   旧数组配额先于共享聚合配额，保留失败原子性和成功计数。
3. 重复资源事件可以压缩，但只有证明计费及位置一致后才启用；无法精确
   核算的结构继续不准入，不能只保存总计数替代资源协议。
4. Runtime 查表仍建立当前数组引用、索引和检查，不缓存目标执行的读取。
   真正的磁盘命中与同会话第二次调用都保持原有残留语义。
5. 扩展 [benchmark 工具](../scripts/benchmark.py)，加入缓存模式、磁盘
   开销、跳过求值和独立进程测量；新增封闭生成器基准作为支持用例。

验收：精确配额及减一限制、零限制、计算边界、多宽度/bool 数组、同会话
复用、新数组实参构造都正确；预热后所有低预算错误保持代码、顺序、位置
与路径。热缓存后的 Runtime 索引执行测试覆盖有效/越界输入。
复用返回值与恢复解释一致，不通过新准入改变旧测试的 Stage。

交付关闭/冷/热的全部测量样本、机器/工具链/源码与二进制身份。分别报告
依赖验证、资源核算、编码、IO、恢复与实际求值成本；没有速度收益时保留
正确性结果并记录原因，不跳过测量或宣称数组持久化已解决内存问题。
C2a/C2b 完成后评估是否扩展准入，不在本计划中默认启用所有普通编译。

## C3a：模块级 Provenance 二进制快照

依赖稳定 Anchor 和文件 CAS，以现有真实 P0 分析快照为对象。
先交付可独立导出、打开和查询的模块快照实验，不让恢复图参与 Stage 决策，
也不把这项能力当成整模块增量缓存。

实施内容：

1. 按 RFC 定义 Header、Root、Summary、Node、Edge、Decision、Site/String
   section，采用未压缩 wire records、显式 section directory 和偏移读取。
   Import 和压缩块是后续能力，第一版不生成未支持引用。
2. 模块语义快照与源码位置映射分开，保留当前绑定、局部契约、稀疏决策、
   符号参数作用域、摘要环及 `Incomplete` 等已有覆盖语义。
3. 由只读句柄拥有文件/缓冲及验证状态，查询入口不依赖 Analyzer/HIR
   生命周期。第一版允许完整读取/解码，不声称已经减少构建峰值或实现
   所有按需加载；可单独按 section 读取并验证。
4. 恢复后复用当前查询逻辑比较值来源、效果来源、调用上下文与决策；
   第一版可先构建新的 FrozenGraph。真正可卸载的读取 API 在 C4 独立设计。
5. 测量对象大小、校验/读取/解码与查询成本、位置对象变化及峰值内存。
   连续 NodeId 直接定位，不为每个节点建哈希表。

验收：真实模块 round-trip 后所有绑定/契约与 P0 决策等价；调用摘要不会
串实参，递归截断/覆盖状态保持；销毁 AST、HIR 和 Analyzer 后仍可查询。
空白改动后的当前位置正确，语义图对象无需因位置映射变化重写。
未知必需 section、越界/重叠区间、非法 ID、错误摘要作用域及截断被拒绝，
从缓存加载失败可重新分析。循环摘要是合法输入，不被格式验证误判为坏图。

本轮不强制采用 OnDiskHashTable、mmap 或压缩；入口索引和读取策略通过
后续测量选择。快照读取能力和语义结果复用分别报告完成状态。

## C3b：符号残留模板与证据关联恢复

依赖 C3a 的证据恢复及 C2 的语义/资源协议。现有缓存保存 HIR 残留定义，
因此首个接入恢复符号 HIR 模板，再走已有 HIR-to-MIR lowering 和验证。
直接保存验证后的 Pagos SSA MIR 是后续可选扩展，不绕过当前流水线。

首批选择非递归、标量参数/结果的闭合特化，例如静态 factor 与 Runtime
value 的 `scale`。先排除嵌套普通调用、外部/global 符号引用和无法精确
恢复资源状态的模板；函数内部的支持效果仅在其编码及调用身份验证完成后
逐项加入。未用 Runtime 参数但结果已知的内联路径仍可正常回退。

实施内容：

1. 保存 Runtime 槽的类型/约束与 Comptime 参数值，恢复符号参数作用域、
   当前 module 内的定义引用和独立调用节点；不保存首次调用方来源或编号。
2. 结果、必需精简证据和资源协议通过同一 manifest 原子关联，不能混用
   不同依赖版本。缺必需证据时重算，缺可选详情时明确报告可用性。
3. 按当前会话首次创建定义的规则预留/计入残留特化数；调用方实参工作仍
   每次分析并保留。恢复不得将两个效果执行合并成一个定义执行。
4. 恢复后验证类型、参数与目标，经现有 MIR 验证后才发给 LLVM。活动
   定义和未完成递归组件不进入磁盘，整个失败组件不留下可复用项。

验收：`scale(4, a)` 与 `scale(4, b)` 共享定义，各自解释只指向自己的
实参；两次调用仍产生两次工作。限制改变、类型/目标变化、符号或必需证据
缺失正确回退；现有递归、局部契约、早返回、volatile 及未用实参用例
保持行为，未准入项不能被意外导入缓存。

交付可复用的非递归模板范围及真实执行/解释对照。对嵌套调用的扩展需要
子查询资源协议与逻辑 memoization 恢复另行验收，不能仅增加 codec。

## C4 与存储优化的后续安排

完成上述轮次后，依据真实数据拆分后续工作：

- 依赖精度：将整模块指纹拆成定义、类型与实际读取查询，验证编辑路径变化
  和命中后依赖导入；再研究结果不变时继续复用与字段敏感查询。
- 函数快照：明确 Import/根 manifest 与递归组件发布，避免循环内容哈希。
- 读取与内存：比较偏移读取和 mmap、建立块 lease/生命周期，再研究有界
  压缩缓存及构建期发布/释放；保持旧 span 契约直到替代接口完成。
- 嵌套资源：恢复子查询逻辑命中状态、成本及可恢复结果引用，检查前置
  会话状态和物理淘汰不改变预算。
- 索引优化：入口查找慢时比较排序表与 LLVM OnDiskHashTable；文件元数据
  开销显著时比较批量索引/pack 与 libmdbx/SQLite。数据库不是固定轮次。
- M5 输入与 LSP：与各自能力/源码快照工作对接，未实现前不加入新的
  文件系统读取能力或编辑器接口。

数据库决策须展示查询频率、文件数量/IO、维护成本和并发写入实测；大图
尺寸或“库看起来更轻”不足以成为选型理由。文件系统仍可作为长期后端。

## 各轮共同的验证与交付规则

语义工作每轮都有 GoogleTest 正反例、lit 的跨进程缓存对照，以及残留
执行证据。协议/存储独立轮次使用对应故障、稳定性与生命周期测试；不要求
尚未接入编译器的轮次伪造热缓存命中。

```sh
cmake --preset debug
cmake --build --preset debug
ctest --preset debug
python3 scripts/check_docs.py
git diff --check
```

修改 C++ 按 `.clang-format` 检查。新 codec、文件读取、长度运算及恢复路径
