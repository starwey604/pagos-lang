# 工作集、崩溃回收与构建峰值 C4b3b

状态：2026-10-16 本轮及 C4b 实验范围验收完成。默认 memory，spill 仍显式开启。

本轮承接 [C4b3a](provenance-trace-c4b3a.md)，实现构建工作集计量、过期 weak
映射回收、Analyzer 收尾释放，以及真实进程崩溃后的显式任务目录回收。
设计与后续安排见 [RFC](cache-architecture-rfc.md) 和
[实现计划](cache-implementation-plan.md)。

## 身份与生命周期

Recorder 原先调用完整 `build_cache_identity`，只取定义和模块指纹，却临时
生成整模块的 SourceAnchor 数组。现在使用
[DefinitionCatalog](../include/pagos/stage/cache_identity.h)：与完整身份共用
同一 AST/schema 遍历和指纹编码，校验相同的类型、目标、位置、深度、字节
及总位置数量限制，但不保存位置表。它使用独立返回类型，不可冒充位置齐全
的 CacheIdentity 交给持久化/位置解析接口。完整快照和语义缓存适配器继续
使用完整身份；格式和语义指纹未改变。

Recorder 的 weak HIR 映射仍按控制块验证身份，允许已销毁表达式的地址被
重新使用。现在按几何增长阈值删除过期项，收尾时再扫描一次，释放被 weak
引用保留的控制块及可能的 make_shared 合并分配区。仍存活的表达式、已记
节点、决策和契约根均保留；清理不改变 NodeId 或重算语言预算。全存活映射
的扫描次数随表规模几何增长，避免每固定若干节点扫描整个大表。

Stage 完成证据冻结和必要的语义缓存验证/发布后，释放 Analyzer 的特化表、
作用域、调用工作表、参数 trace 表及 ScalarCache 身份/队列。统计、查询上下文
和返回的 HIR/Provenance 保持有效；同一个 Analyzer 可以重新分析，新旧模块
可以同时查询。单纯释放这些表不保证分配器把页面归还 OS，也不等于降低构建
时已经发生的峰值；真实 RSS 单独测量。

## 显式任务目录回收

[EvidenceSession](../lib/stage/evidence_session.cpp) 在独立临时命名空间中建立
`session.lock`，写入版本标记并持有 OS 独占锁直到最后一个 builder/view
释放。进程内注册表和互斥锁补充保护进程级文件锁；父目录规范化消除祖先
符号链接造成的同进程路径别名。正常析构删除自有目录，不删除父目录。
解码后的独立 lease 仍可跨文件删除存活。

```sh
build/debug/pagosc reclaim-evidence build/evidence-tmp
```

该命令调用 `reclaim_evidence_sessions`，只检查匹配任务前缀的直接子目录，
在锁空闲且版本标记完整匹配时删除。活动 builder/view、未知版本、缺失或
不完整标记及目录符号链接会跳过；无关文件不动。不存在的父目录不会创建，
空路径和非目录失败。统计为 examined/reclaimed/active/skipped/errors。
没有默认启动扫描，也不把 `--cache-dir` 当作临时任务回收目录。

进程被杀后不会运行 RAII，目录可以留下部分临时文件或完整 CAS 叶对象；
新任务使用新命名空间，不采用、不删除旧目录。调用方可以在确认任务退出后
显式回收。创建目录但尚未完成标记的极早期崩溃，以及旧版无标记目录，不在
自动识别范围内，需离线检查后处置。这里不是可恢复构建/checkpoint 协议。

磁盘额度仍计 CAS payload 和每对象 49 字节封装；每任务额外的 26 字节
版本锁标记、文件系统元数据及目录开销不计入该逻辑额度。成功发布 CAS
使用硬链接，发布后的崩溃可能同时留下内容相同的完整临时硬链接和叶对象。
没有成功语义 manifest 的临时目录不会成为可命中缓存。

## 工作集计量

[计量结构](../include/pagos/stage/memory_stats.h) 与
[实现辅助](../lib/stage/memory_accounting.h) 分别记录：

- 站点/标签、根/名称、StageDecision、作用域和决策/契约索引的实际 vector
  容量，特化身份/参数的堆字符串及常量数组负载。
- Recorder 收尾前的 weak/参数/摘要映射、桶数组、摘要和活动帧容量，定义
  身份目录，以及 memo 峰值项数、收尾项数、过期和已删除项数。
- 原图容量、冻结视图目录容量；临时 builder 目录/摘要及活跃/驻留/lease
  容量继续由 EvidenceBuildStats 报告。Recorder 当前使用 Append，不建立
  节点驻留去重索引；已有独立 SelectiveIntern 实验不混入该测量。
- Analyzer 清理前后的表、参数负载和 ScalarCache 身份/队列容量。
  延后发布队列的历史 payload 峰值仍由原有 CacheTelemetry 单独报告。

`measure_memory` 只控制可选收尾扫描；不是资源额度。实验工具的 census
进程和 CLI `--spill-stats` 会打开它，普通编译不做完整容量扫描。前缀路径
仍使用 C4b3a 的独立去重 census。表容量包含 map value 对象和桶，但不含
实现私有链指针、shared_ptr 控制块、分配器、固定对象头、路径配置和 codec
临时缓冲。Recorder 和 Analyzer 是不同收尾时刻的快照，不能相加后充当同一
瞬间的峰值。census 自己的遍历/去重索引也会分配内存，因此独立起进程。

这些计量显示剩余热元数据仍随输入增长；站点、根和决策继续常驻，以保持
现有引用/span 接口和即时解释能力。显式 compressed 查询与快照/函数导出
仍会请求兼容整图恢复。C4b 的驻留额度只约束图缓冲，不是总编译器内存限制。

## 真实进程验证

[进程 probe](../tests/stage_spill_probe.cpp) 运行真正的解析、类型检查、Stage、
纯标量缓存以及大 Runtime 函数。父进程在以下真实 IO 边界强制终止子进程：

1. 首块临时文件只写了一半，还没有 CAS 叶对象。
2. 首个 CAS 叶对象已经原子发布，写入调用尚未返回。

[父进程测试](../tests/stage_spill_process.py) 在终止前验证回收器跳过活动目录、
语义缓存尚不存在；终止并回收进程后验证旧目录仍在。新任务可以完成同一
程序，旧目录内容不变，旧任务没有 manifest，随后显式回收只删除死亡任务。
未知版本目录留下，重复回收幂等。另一个进程用有限磁盘额度让 Stage 在已写
至少一个块后辅助失败：语义写入为零、已有候选被挡住，诊断、HIR 签名和 Fuel
与内存模式一致，正常退出清理自有目录。

单测还覆盖同进程 builder/冻结视图锁保护、祖先路径别名、过期 folded HIR
回收后全量快照字节一致、元数据计量、Analyzer 实际清空容器，以及重新分析
后旧模块查询仍有效。定义目录与完整身份逐项比较，并覆盖额度、目标和无效
位置的共同拒绝行为。原有缺块、损坏、封存发布故障、额度回退、暂停游标、
递归/契约/投影以及残留执行回归保留。

## 测量协议

[测量脚本](../scripts/benchmark_stage_working_set.py) 默认在工作区
`build/benchmarks/` 下建立新的临时目录，记录底层文件系统和设备；可用
`--work-dir` 指定目标文件系统。每份真实 `.pgs` 都解析、检查并在 Stage 中
生成 Recorder 定义身份，语义持久化缓存关闭。标量残留特化和全 Comptime
数组参数缓存分开测量，匹配当前实现实际支持的路径。

```sh
cmake --build --preset release --target pagos_stage_spill_bench
python3 scripts/benchmark_stage_working_set.py \
  --output build/benchmarks/stage-working-set.json
```

每档每模式预热 2 次、采集 7 次，build 和 build+native-query 各起独立子进程；
census 另起进程。全部构建和回归停止后顺序运行，无绑核和固定频率，不清理
OS 页缓存。原生查询选择 `aa`，不导出、不恢复整图；对照节点/站点/根/决策、
Fuel、来源签名和状态数，所有 spill 样本保持 `materialized=0`。

构建峰值为 Stage 返回后 `/proc/self/status` 的 VmHWM，包含本次 exec 后的
启动、前端、身份与构建，不含后续查询。query 子进程先保存它，再通过
`/proc/self/clear_refs=5` 重置高水位；立即在查询结束后记录查询窗口 VmHWM
和查询开始前 RSS。这个窗口包含仍驻留的前端/HIR 基线，不是新进程独立读取器。
wait4 退出高水位和构建高水位取最大值另行保存，包含枚举/析构；Linux fork/
pre-exec 继承的父进程 RSS 下限可能影响小任务的 wait4 值，因此构建比较使用
本次 exec 的 VmHWM。查询时钟排除高水位重置和统计读写。

`/proc/self/io` 在文件枚举结束、输出/析构之前采样，覆盖 loader、源码、CAS
写入和发布校验读取。rchar/wchar/syscr/syscw 是内核读写计数，read_bytes/
write_bytes 是内核存储记账，不代表设备上实际发生的物理 IO；热页缓存、
文件系统和退出时取消脏页都会影响它们。目录/unlink 等元数据操作、统计点
之后的清理及输出不在该字节窗口内。计数包含测量本身读取 proc 文件和重置
高水位的小额开销。CAS payload、封装、总文件数与锁标记另行列出。

本轮定义身份与语料、文件系统和采样窗口均有扩展，不能直接用 C4b3a 的
历史报告做性能归因。对照只在本轮同一二进制的 memory/spill 之间进行。

## 本机结果与结论

[原始 JSON](../benchmarks/results/stage-working-set-c4b3b.json) 保存 28 组共
196 个正式样本、每组预热配置、14 个独立 census 样本、源码/二进制/CMake
身份、工具版本和全部范围/IQR。机器为 AMD Ryzen AI 9 HX 470、Linux 7.2.10、
Clang/LLVM 23.1.1、Python 3.14.8，临时文件位于工作区的 **btrfs** 文件系统。
以下为仅构建进程的中位数；RSS 为本次 exec 后 VmHWM，单位 MiB。

| 输入 | memory RSS | spill RSS | memory Stage ms | spill Stage ms |
| --- | --- | --- | --- | --- |
| 2 函数 × 2048 步 | 32.20 | 32.79 | 7.480 | 10.295 |
| 32 函数 × 512 步 | 63.96 | 61.73 | 27.512 | 34.942 |
| 128 函数 × 512 步 | 187.27 | 180.03 | 122.516 | 152.305 |
| 32 函数 × 128 步/Runtime 分支 | 52.69 | 52.37 | 20.012 | 26.997 |
| 4096 个局部契约 | 25.20 | 25.76 | 2.239 | 8.393 |
| 512 个残留特化/8 个 Comptime 标量 | 32.11 | 32.65 | 6.000 | 11.457 |
| 512 个纯求值特化/64 元素数组参数 | 34.36 | 35.14 | 10.340 | 10.729 |

最大档 **131,975 个图节点**，构建峰值范围为 memory **186.49–188.52 MiB**、
spill **179.73–180.82 MiB**。7 个独立进程样本范围不重叠，中位数下降
**7.25 MiB，约 3.9%**。同档 build+query 子进程中，查询窗口峰值中位数
分别为 **187.80/180.32 MiB**，查询前基线为 **187.67/180.20 MiB**；
首查中位数 **0.064/0.185 ms**。窗口包含前端/HIR 基线，不能把约 7 MiB
差值归因于查询状态本身；它主要继承构建后的驻留差异。

最大档实际释放累计活动图容量 **6,709,536 字节**，builder peak-owned
**49,152 字节**；冻结读取器另有目录容量。内存模式的最终图容量为
**10,488,832 字节**，与累计活动容量不同，后者可能反复计算复用后的块。
这些数字不是 RSS 的替代：临时编码、分配器和容器增长均影响高水位。

小档和高契约/参数密度输入没有稳定净收益，有些略增加 RSS。32 函数和
Runtime 分支样本存在范围重叠，不推广中位数差。最大档 Stage 中位数约慢
24%，写盘和验证有实质成本。因此本轮只确认显式 spill 在较大图上有可复现
的构建峰值收益，不将其设为默认，不宣称总体编译加速或固定比例节省。

下表列各档首个正式 spill 查询样本的 IO/文件计数。CAS、文件和 syscall
数量在这批样本中一致；rchar 有少量 proc 字符差异，内核 write_bytes 也随
文件系统记账变化。最大档为 4,734,976–4,784,128 字节，完整分布见 JSON：

| 输入 | CAS 文件 | 全部文件字节 | 首查对象/字节 | rchar/wchar | 内核 write_bytes |
| --- | --- | --- | --- | --- | --- |
| 128 函数 × 512 步 | 162 | 4,099,377 | 2 / 51,503 | 5,723,425 / 4,099,378 | 4,734,976 |
| 4096 个局部契约 | 8 | 193,733 | 1 / 647 | 214,432 / 193,734 | 208,896 |
| 512 个残留特化 | 11 | 283,183 | 2 / 52,517 | 377,593 / 283,184 | 327,680 |

最大档另有 1 个锁标记文件，共 163 个文件；CAS 含封装为 4,099,351 字节，
payload 为 4,091,413 字节。其 syscall 读写计数为 **543/650**，构建器 CAS
重读为 **0**；rchar 仍包含 FileStore 发布校验读和源码读取，不能只拿
build-reads=0 当作没有总读取。该批热页缓存样本 read_bytes 为 0，不代表
磁盘存储无读成本；write_bytes 也不是已经完成持久写盘的吞吐或字节保证。
查询子进程的 wchar 比总文件内容多 1 字节，来自重置高水位的 proc 写入。

census 揭示下一阶段仍需重视的常驻部分：

- 最大档站点/标签 **13,832,979 字节**、根 **16,384 字节**、作用域/索引
  **75,776 字节**、特化负载 **42,496 字节**、共享路径 Step 小计
  **6,310,032 字节**。Recorder 收尾前映射/桶/摘要 **5,615,800 字节**，
  定义目录 **77,340 字节**；这些工作表随后随 Recorder 释放。
- Runtime 分支输入有 **4,064 条决策**，其数组容量 **229,376 字节**。
  契约输入有 **4,101 个根**，根数组容量 **524,288 字节**。站点/根/决策
  的保留成本没有被图缓冲统计掩盖，也没有被宣称已经卸载。
- 契约输入删除 **4,098 个过期 memo**，收尾余 **12 项**；原节点、契约与
  决策仍可查询。数组参数输入删除 1,024 个过期项。
- 标量残留特化的 Provenance 身份/参数负载为 **1,259,520 字节**，Analyzer
  特化参数为 **626,688 字节**；纯数组参数特化的 Analyzer 参数负载为
  **557,056 字节**。所有 census 的 Analyzer 清理后三项容量均为 0。
  HIR 和已冻结证据仍持有各自需要的数据，并非删除语言结果来换取节省。

本轮完成 C4b 的显式分段构建、旧块读取/释放、元数据计量与工作表回收、
存储/额度辅助失败、语义发布门禁、真实进程崩溃与回收验证，并在同机独立
Release 进程中满足实际构建峰值下降门槛。仍保留 32 位 ID、常驻热元数据、
显式整图兼容恢复和非全编译器内存额度等边界。后续 C4c 处理查询队列、
visited/前驱等任务状态的卸载与跨进程 checkpoint；不自动扩大本轮承诺。
